# Recording `docs/demo.gif`

## Why not VHS

`docs/demo.tape` exists, validates, and runs — but it **cannot** produce a
usable demo, so do not ship its output.

VHS renders through `ttyd` + `xterm.js`, a browser terminal. This plugin's whole
job is putting pixels in the preview pane through a terminal graphics protocol,
and xterm.js implements none of them. Three attempts, in order:

| Attempt | Result |
| --- | --- |
| Plain tape | Preview pane filled with a grid of placeholder glyphs |
| Unset `KITTY_WINDOW_ID` & friends | Pane went completely empty |
| Also force `TERM=xterm-256color` | Still empty |

The glyph grid appears when the recorder is itself running inside Kitty: yazi
inherits `KITTY_WINDOW_ID`, concludes it is Kitty, and emits Unicode-placeholder
escapes. Unsetting that gets rid of the glyphs but not the problem — yazi's
terminal capability probe false-positives under `ttyd`, so it still selects a
graphics driver (Sixel or the old Kitty protocol) and writes escapes that
xterm.js discards. `<project>/.local/state/yazi/yazi.log` shows no
`[Drivers] Falling back to chafa` line, confirming a driver was chosen rather
than the Chafa text fallback.

Net effect: the recorded GIF shows an empty preview pane. That is worse than no
demo, because it looks like the plugin is broken.

## What to do instead

Record a real terminal, where the preview actually renders.

### 1. Build the environment

```sh
sh docs/demo-env.sh          # -> /tmp/epub-preview-demo (config + generated books)
```

The books are generated by `make-demo-epub.sh`, so the recording contains no
copyrighted material. The demo config is isolated (`YAZI_CONFIG_HOME`) and holds
only this plugin, reusing your own `theme.toml` and `flavors/` when present.

### 2. Record

In a graphics-capable terminal (Kitty, Ghostty, WezTerm, iTerm2 — anything yazi
previews images in):

```sh
YAZI_CONFIG_HOME=/tmp/epub-preview-demo/config yazi /tmp/epub-preview-demo/books
```

Press `j` through the three books, then screen-record roughly 8 seconds with
QuickTime (`⌘⇧5`) or `screencapture -v`. Keep the terminal window tight so the
crop is easy.

### 3. Convert to GIF

```sh
ffmpeg -i recording.mov \
  -vf "fps=12,scale=1200:-1:flags=lanczos,split[a][b];[a]palettegen=stats_mode=diff[p];[b][p]paletteuse=dither=bayer:bayer_scale=3" \
  -loop 0 docs/demo.gif
```

Crop to the terminal first if the recording caught more than the window:

```sh
-vf "crop=W:H:X:Y,fps=12,..."
```

### 4. Reference it

```markdown
![Previewing EPUB covers in Yazi](docs/demo.gif)
```

Aim for well under 5 MB; GitHub renders it inline but large GIFs load slowly.
